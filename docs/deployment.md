# Render deployment

The repository root is already the backend project and is the correct Render
service root. Do not create a nested Git repository inside `backend/`; connect
Render to the existing GitHub repository instead.

## Render service

This repository includes [`render.yaml`](../render.yaml), which configures:

- Python build with `uv`
- Alembic migrations before startup
- Uvicorn on Render's `$PORT`
- `/health` as the health check
- generated `AUTH_SECRET_KEY`

You can either use the Render blueprint or create a Web Service manually with
these commands:

```text
Build Command: pip install uv && uv sync
Start Command: uv run alembic upgrade head && uv run uvicorn backend.api.main:app --host 0.0.0.0 --port $PORT
Health Check Path: /health
```

Set the service root to the repository root. Do not commit `.env` or any
credential values.

## Required environment variables

Set these in Render's Environment tab:

```text
DATABASE_URL
AUTH_SECRET_KEY
GOOGLE_CLIENT_ID
GENERATION_MODEL
GENERATION_API_BASE_URL
GENERATION_API_KEY
VERIFICATION_MODEL
VERIFICATION_API_BASE_URL
VERIFICATION_API_KEY
SERPAPI_API_KEY (optional, enables web remediation)
CORS_ORIGINS
EMBED_DIM=256
```

Generation and verification can use separate OpenAI Chat Completions-compatible
providers. Configure provider-specific model names, base URLs, and API keys;
changes apply after the service restarts. See [remediation.md](remediation.md)
for the supported endpoint contract.

`AUTH_SECRET_KEY` is generated by Render in the blueprint. Keep it stable:
changing it invalidates all existing login tokens. `DATABASE_URL` must point to
the Render PostgreSQL database.
The URL is normalized by the application and external connections require
`sslmode=require`.

Set `CORS_ORIGINS` to the deployed frontend origin, for example:

```text
https://your-frontend.example
```

Do not use `*` when credentials are enabled.

## Important storage note

Render web-service filesystems are ephemeral unless a persistent disk is
attached. The current pipeline uses persistent local Chroma storage, so attach
a persistent disk and run a single backend instance. PostgreSQL stores durable
chat and authentication data but is not used as the vector store.

## First deploy checklist

1. Provision Render PostgreSQL for application data.
2. Configure the environment variables above.
3. Deploy the web service from the existing repository.
4. Confirm `GET /health` returns `{"status":"ok"}`.
5. Confirm `GET /openapi.json` is reachable.
6. Register a test account and verify chat creation, upload, questions, and
   message history.
